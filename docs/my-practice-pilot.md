# Моя практика — изолированный пилот (GitHub #13)

Только синтетические врач, клиники, услуги, цены и блоки занятости.
- Ветка: `feat/my-practice-multi-clinic-pilot`.
- Тест: `npm run test:my-practice`, сборка: `npm run build`.
- В Preview-проекте `tochka-opori-test` можно добавить переменную `VITE_ENABLE_MY_PRACTICE_PILOT=true` **только для этой ветки**.
- При включённом флаге доступна отдельная страница `/specialist/my-practice/demo`; вкладка также видна в существующем авторизованном кабинете.
- В production и других ветках флаг по умолчанию выключен. Никаких новых API, миграций, БД и платёжных интеграций.
- Запись, внешние ссылки, оплата и медицинские действия отключены. Календарь — блоки занятости, **не доступные слоты**.
- Публичная демостраница НЕ получает данные от `/api/specialist`, токены, медицинские карты и реальные сведения о пациентах.
- Согласие клиники, юридический исполнитель медицинской услуги, реальные права врача и разграничение данных — обязательные этапы перед запуском.
- Для приёмки: открыть демо-путь, переключить Обзор/Услуги/Занятость, проверить фильтры, следующую неделю, мобильный экран, отсутствие пациентских запросов и ошибок.
- После просмотра: для реального MVP разработать серверные модели сервисов и уполномоченных клиник, но **не** склеивать медицинские карты разных организаций.

Исследовательская ветка не разрешена к слиянию без отдельной проверки безопасности, UX и юридического контура.

## Редактор каталога — демонстрационный шаг 2
- В разделе **Управление** можно добавлять, редактировать, архивировать и восстанавливать синтетические услуги, отдельно по клиникам.
- «Сохранить черновик в браузере» использует только sessionStorage текущей вкладки; **ни сервер, ни клиники не видят этот черновик**. При закрытии сессии данные могут исчезнуть.
- Серверного каталога, авторизации клиник на публикацию и доступных слотов всё ещё нет. Подмена JSON в браузере не позволяет публиковать ссылки: поле bookingUrl берётся из фиксированного демо-набора, публикация заблокирована.
- Приёмка: добавить услугу в «Клинику Центр», изменить цену, архивировать, восстановить; проверить фильтры вкладки «Услуги»; сохранить черновик и перезагрузить экран; сбросить данные.
- Тесты `npm run test:my-practice` теперь выполняются также в `npm run build`. Нет миграций, новых баз и изменений API.
- Следующая итерация: отдельно спроектировать серверную модель `expert_id / organization_id / service_offer`, подтверждение полномочий клиники и RBAC. До этого реальную запись и оплату не включать.

## Редактирование напрямую из каталога — шаг 3
- Во вкладке «Услуги» под каждой карточкой доступна кнопка **«Редактировать»**, открывающая прямо в карточке форму с текущим названием, ценой, длительностью и форматом.
- «Сохранить изменение» обновляет активный черновик; **«Сохранить черновик в браузере»** на этой же вкладке фиксирует его в sessionStorage для текущей сессии. Есть «Отмена», которая не вносит правок.
- Защита бизнес-логики не меняется: редактирование разрешено только в исходной клинике, архивные услуги скрыты, ссылки записи и разрешения клиники нельзя редактировать, реальных платежей нет.
- Проверки: редактирование исходной услуги, сохранение и перечитывание черновика, запрет редактирования из другого контекста клиники. Подтверждать браузерный smoke-test отдельно.

## Модель комиссии и приглашения — шаг 4 (только Preview)

**Экономика**
- В разделе «Финансы» отображается модель **20% платформе / 80% медицинской организации** от оплаченной стоимости консультации, до налогов, эквайринга и расходов.
- Расчётные суммы в копейках; базовая ставка `MY_PRACTICE_DEFAULT_FEE_BPS = 2000`; сумма комиссии фиксируется по версии условий договора/сделки перед оплатой. Изменение ставки не должно менять уже созданную оплачиваемую услугу.
- До подтверждения платежа нет начислений. После подтверждения — удержание; расчётную комиссию можно допустить к выплате только после выполнения услуги и окончания срока удержания. Возврат формирует обратную запись по первоначальной ставке, не удаляет историю.
- Раздел предлагает выбор услуги, четыре стадии оплаты/выполнения и имитацию полного/частичного возврата. **Это чистый расчёт в браузере, не фактические начисления, платёжная форма или право платформы получить комиссию.**
- Существующая **25% партнёрская программа за оплаченный AI-трафик** — принципиально отдельный продукт, другая база и другой получатель. Нельзя применять обе ставки к одной и той же базе по умолчанию.
- Прежде чем разрешать настоящие платежи, согласовать модель договора: юридический исполнитель медицинской услуги, касса и чек, агентирование / договор возмездных услуг, способы подтверждения оплаты у клиники, возвраты и сверка. Если пациент платит клинике напрямую, платформа не вправе считать это своей собранной выручкой.

**Пациенты / ссылки**
- Подтверждено в основном коде: авторизованный врач в Support может вызвать `createInvitation` через `/api/specialist`. Сервер создаёт криптографический токен, хранит только SHA-256, ссылка действует 7 суток; есть отзыв и принятие приглашения в защищённой сессии пациента.
- Раздел «Пациенты» показывает четыре этапа: публичная страница специалиста → индивидуальное согласуемое приглашение → кабинет пациента → подтверждённый канал записи конкретной клиники.
- Демоверсия **не генерирует новые токены**, не создаёт реальных пациентов, не содержит персональных данных и не ведёт медицинскую переписку.
- Ссылки на запись/платёж в клиники включать только после подтверждения полномочий врача и договора с медицинской организацией; не приравнивать пустые интервалы календаря к свободным слотам.
- Будущая реализация должна связывать конкретный `expert_id`, `organization_id`, вид услуги, согласие пациента, права на медицинские данные и аудит; без открытия общего доступа к картам разных клиник.

Тест: `npm run test:my-practice` теперь включает unit-проверки комиссии, удержаний и возвратов. Production, Supabase, платёжный провайдер и API не меняются.

## Редактируемый календарь — шаг 5 (только Preview)

- Во вкладке **«Занятость»** поддерживаются два вида учебных событий: **блок занятости** (приём в клинике, личное время, отпуск, недоступен) и **учебная запись** (услуга, вымышленный пациент №1–4, статус).
- Кнопки **«+ Запись»**, **«+ Занятость»**; в каждой колонке дня **«+ Добавить»**, на каждом событии **«Изменить»**. В форме: дата, место приёма, начало и конец, тип; у учебной записи также услуга, учебный псевдоним и статус.
- По умолчанию в учебной записи длительность подставляется из выбранной услуги, а конец можно изменить вручную. **«Удалить событие»** работает после подтверждения.
- Статусы: ожидает, подтверждена, отменена, завершена. Цветовая легенда помогает ориентироваться; отменённое событие видимо, но не блокирует время.
- Одновременные активные события **в разных клиниках тоже конфликтуют** (врач один). Система не разрешает добавить или перенести событие поверх другого активного события. Смежные интервалы допустимы.
- Все пять первоначальных блоков занятости редактируемые ручные демоблоки, несмотря на названия клиник. В будущей версии внешние записи клиник останутся только для просмотра или согласованных действий через интеграцию.
- Для пациента доступны **только фиксированные учебные псевдонимы**, свободного текстового поля с персональными данными нет. Реальные записи, ссылки, звонки, сообщения, цены и платежи **не создаются**.
- Кнопка **«Сохранить расписание в браузере»** записывает в отдельный sessionStorage-ключ `my-practice:synthetic-schedule:v1`; его хранение не затрагивает черновик услуг. Есть **«Сбросить календарь»**.
- При восстановлении из sessionStorage вся структура заново валидируется; подмена source/клиники/услуги/статуса, дублирующиеся идентификаторы и пересечения отклоняются. Защита от подмены на клиенте не заменяет серверную RBAC.
- `npm run test:my-practice` теперь тестирует добавление, правку старых блоков, статусы, перенос, пересечения, удаление и сохранение. Это всё ещё чистый UI без Supabase/API.
- Следующая задача: серверная схема врач ↔ клиника ↔ услуга ↔ запись; атомарное резервирование, права доступа и синхронизация с МИС при наличии соглашений. Не превращать ручной демо-календарь в самостоятельное медицинское расписание.

## Серверный черновик — шаг 6 (защищённая основа)
- SQL: `supabase/migrations/20261106053005_my_practice_synthetic_workspaces.sql` — отдельная таблица в уже существующей тестовой базе, без новой Supabase.
- Таблица `my_practice_synthetic_workspaces`: один JSONB workspace на врача, scope=synthetic, числовая версия оптимистической блокировки.
- RLS включён, нет прав/политик anon/authenticated; только service_role с серверной проверкой сессии и membership.
- Действия в `/api/specialist`: `getMyPracticeWorkspace`, `saveMyPracticeWorkspace`. Запросы разрешены только same-origin, только Preview и только при совпадении разрешённого Supabase ref с SUPABASE_URL.
- Точные gate-переменные: `MY_PRACTICE_SERVER_ENABLED=true`, `MY_PRACTICE_ALLOWED_SUPABASE_REF=eehyehlhiyztciaezaus` — исключительно для feature-branch Preview.
- Данные проходят строгую проверку: только активные организации данного врача, 0–30 услуг на организацию, 0–200 событий, только учебные псевдонимы, без телефонных номеров, заметок и пациентских данных.
- Нельзя редактировать записи другой клиники или сохранять пересекающиеся активные события. При несовпадении версии HTTP 409, автоматического перезаписывания нет.
- Публичный `/specialist/my-practice/demo` пока не загружает и не сохраняет серверные данные: он работает на прежних локальных черновиках и не требует входа.
- Это только технический каркас. Реальные пациенты, медицинская переписка, назначения, платежи и интеграции МИС НЕ разрешены в зарубежном тестовом контуре.
- Следом: применить миграцию исключительно к TEST, проверить RLS/адвайзеры и API, после этого сделать интерфейс синхронизации в авторизованном кабинете.

## Защищённый интерфейс серверного черновика (Preview)

Реализован отдельный компонент `MyPracticeServerWorkspace.jsx`, доступный **только после авторизации врача** и только при `VITE_ENABLE_MY_PRACTICE_SERVER_UI=true`. Публичная демостраница не обращается к API и продолжает работать локально. Подробности настройки тестовых переменных Vercel, использования и ограничений: `docs/my-practice-server-ui-guide.md`.

До подтверждения пары тестовых `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` серверный переключатель `MY_PRACTICE_SERVER_ENABLED` оставлять выключенным; нельзя автоматически включать через общие переменные Preview. Вспомогательные тесты включены в `npm run test:my-practice`.

## Бизнес-процесс «Платные приёмы» — прототип 0.8

- Справочная вкладка переименована в **«Мой календарь»**. События разных клиник не связаны с оплатой и не тарифицируются.
- Добавлена вкладка **«Платные приёмы»**: врач выбирает учебную услугу и создаёт свободный слот, не пересекающийся со справочной занятостью и другими платными слотами.
- Каждому учебному слоту соответствует отдельная **демонстрационная ссылка пациента** `/specialist/my-practice/booking-demo?offer=…` с публичным JSON-снимком вымышленной услуги (без секретов и ПДн).
- Пациент видит учебный слот, может временно зарезервировать его на 10 минут, затем **имитировать предоплату**. Подтверждённая симуляция отображается в браузере; отмена имитирует возврат.
- Комиссия 20% от учебной стоимости рассчитывается отдельно от информационного календаря. Состояния: `held`, `expired`, `simulated_paid`, `cancelled`, `simulated_refunded`.
- Система записывает события **только в localStorage данного браузера**, без сервера, реальных пациентов, провайдеров платежей и кассового чека. Кросс-браузерное и межустройственное бронирование отсутствует. В другом браузере публичная демо-ссылка отображает предложение, но не связывает результаты записи с кабинетом автора.
- Это НЕ настоящий booking token (ссылка содержит лишь учебные данные), НЕ платёжная ссылка и НЕ реальное подтверждение записи. Исполнитель показан как не прошедший юридическую верификацию.
- Для коммерческой версии обязательно: лицензированный юридический исполнитель, договор и ОКВЭД, server-side slots/holds/booking с атомарным резервом, платёжный webhook, чеки ККТ и возвраты, российский контур данных пациента, агентская схема.
- Ручная проверка: создать слот → скопировать ссылку → открыть в новой вкладке того же браузера → создать бронь → имитировать оплату → проверить статус у врача после обновления → отменить/имитировать возврат. Проверить занятость и конфликт пересечения.
- Полноценный серверный и браузерный end-to-end тест отсутствует; нельзя включать в Production до выделенного backend и приёмки.

## Редактируемые места работы врача — шаг 0.9

- Раздел «Обзор» показывает справочные **места работы/приёма**, а не лицензированные клиники, подтверждённые платформой. Первоначальные «Север», «Центр», «Юг» теперь можно **переименовать**, сменить адрес/пояснение и **удалить**. Можно добавлять до 20 собственных мест.
- Кнопки «Изменить», «Услуги», «Удалить» доступны непосредственно на карточке каждого места; «+ Добавить место» открывает форму с названием и необязательным адресом.
- Изменения сначала попадают в черновик. **«Сохранить справочник в браузере»** сохраняет места, связанные услуги и календарь; после перезагрузки пользовательские названия сохраняются.
- При удалении показывается точное число удаляемых вместе с местом учебных услуг и событий, требуется явное подтверждение. Если у места есть хоть один платный демо-слот, удаление блокируется до очистки учебных платных слотов в отдельной вкладке. Никакая история сделок не удаляется молча.
- Календарь и редактор услуг работают с актуальным справочником, включая вновь добавленные места. Платный демо-каталог также допускает услуги на добавленном месте, но исключительно как неуполномоченную синтетику.
- `restoreDraftCatalog` принимает добавленные/переименованные/удалённые места, при этом принудительно сбрасывает поля публикации и лицензии; прямую запись в Supabase не включает.
- В редакторе услуг кнопка возврата к исходным данным требует подтверждения и восстанавливает **и каталог, и справочный календарь**.
- Регрессии: `npm run test:my-practice` охватывает создание, переименование, удаление, связь с услугами/календарём, сохранение, запрет удаления при платных демо-слотах и защиту от подмены разрешений.
- Никаких изменений Production, реальных врачей, медицинских карт, лицензий и платёжного провайдера.
