# GPT-Live: закрытый тест Health

Отдельная кнопка в кабинете, старый голосовой режим остаётся доступным.
«Я закончил» только выключает передачу микрофона, оставляя соединение и звук
ответа открытыми. «Говорите» включает микрофон в той же сессии. Завершение
сессии — отдельная кнопка «Завершить разговор» или крестик. Можно просто
сделать паузу в речи, не нажимая кнопку: модель слушает поток автоматически.
Браузер → WebRTC → gpt-live-1; Responses backend → gpt-5.5 (можно задать
HEALTH_LIVE_BACKEND_MODEL). Контекст анкеты/дневника/лекарств читается через
существующую проверку владельца. Инструкции Health сохраняются, формат — речь.
Серверный API использует существующий слот /api/session, action=healthLive.

## Включение

Только закрытый Preview с Vercel Authentication, для внутренних тестировщиков:
VITE_HEALTH_LIVE_ENABLED=true и HEALTH_LIVE_ENABLED=true. Ключ — существующий
OPENAI_API_KEY с доступом к GPT-Live и выбранному backend. В production
сервер принудительно блокирует пилот независимо от флага. Новых миграций нет.
Проверка /models/gpt-live-1 подтверждает лишь видимость модели: полноценный
доступ к Live проверяется созданием настоящего WebRTC-соединения.

## Что измеряет тест

Данные session.usage.updated и session.closed: секунды и оценка стоимости голоса
по $0.05/мин. Это не полная стоимость: backend оплачивается отдельно; UI собирает
total_tokens из вложенных Responses событий без двойного счёта. Не использовать
клиентские значения для списания средств: серверного учёта и сверки пока нет.
Финализация подтверждается только session.closed, сетевой обрыв явно показан.

Клиент закрывает разговор через 5 минут либо после 60 секунд тишины на входном
и выходном аудиопотоке без ожидающего Responses-запроса. При уходе со страницы
или смене устройств отправляет session.close и ждёт финализацию до 15 секунд.
Это клиентский таймер, НЕ гарантированный серверный лимит расходов: фоновые
вкладки, закрытие браузера и обрыв сети требуют отдельного серверного watchdog
и сверки с провайдером перед публичным запуском. Создание соединения тоже платное.
Лимитер запросов существующий, локальный при отсутствии KV, не глобальный бюджет.

## Ограничения пилота

store=false; приложение не сохраняет аудио. Расшифровка только в открытом окне,
не в дневнике/карте пациента. Она не доказывает фактическое воспроизведение.
Новый разговор получает прежний сохранённый Health-контекст, но не прошлую
несохранённую Live-беседу. Записывающие инструменты и hosted search отключены.
Браузеру разрешён только session.close: смена моделей, инструкций, tools и
store через data channel запрещена. Полный API-ключ остаётся на сервере.
Перед созданием нужны согласие, Health client token и доступ к сессии.

Содержательные вопросы направляются к backend инструкцией, а не детерминированным
шлюзом. Пилот не включает прежнюю обработку sendBodyAiMessage (intent routing,
сохранение/кошелёк). Поэтому это тест качества общения, не клинический релиз.
Существующие Support-маршруты не меняются. Перед пациентским запуском нужны
серверное наблюдение, сохранение подтверждённых событий, бюджет, клиническая
проверка кризисных сценариев и анализ передачи/хранения данных.

## Проверка

npm run test:health-live
npm run e2e:health-live
VITE_HEALTH_LIVE_ENABLED=true npm run build

Мок-тесты проверяют права, ошибки, жизненный цикл и интерфейс, не качество речи.
Реально проверить на Preview: доступ модели; 5–10 русских реплик; перебивания;
Safari iPhone/Chrome; динамик/Bluetooth; задержка первого звука; бездействие;
закрытие вкладки/обрыв; финальная стоимость в OpenAI. Тестовые сценарии —
вымышленные, например сон, банкет завтра, вопрос о самостоятельной смене дозы.
