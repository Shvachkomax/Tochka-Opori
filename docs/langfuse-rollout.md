# Langfuse: поэтапное подключение AI-трафика

Дата проверки: 04.11.2026. Ветка: `feat/langfuse-test-observability`. Основа: main после PR #11.

## Цель и границы

Использовать готовые SDK и интерфейс Langfuse для учёта AI-вызовов, моделей, токенов, времени, ошибок и расчётной себестоимости. Собственный код ограничить адаптером к существующим fetch-вызовам и безопасной передачей метаданных.

Langfuse не заменяет баланс пациента, бухгалтерию, платежи и партнёрские начисления. Стоимость, рассчитанная по тарифам модели, является оценкой; окончательные расходы сверяются с провайдером. Тестовые 25% не являются выплатами.

## Результат этапа 1

- Серверный код приложения: Node.js 24, ESM, Vercel Functions. Используется `fetch`, официального OpenAI SDK в зависимостях нет.
- `lib/providers/openai.js` выполняет Responses API, Chat Completions, STT и голосовой анализ. Токены в двух текстовых методах выводятся в лог, но не возвращаются вызывающему коду.
- `lib/modelRouter.js` дополнительно теряет usage при формировании результата. Учитывать вызовы только на уровне конечного списания нельзя: уточнения, повторные попытки и промежуточные операции могут не приводить к отдельному списанию.
- `api/analyze.js` пытается передать input/output tokens в списание после сохранения отчёта. На текущем пути значения могут отсутствовать.
- Для существующих fetch-вызовов подходит ручная instrumentation через официальный `@langfuse/tracing` и экспорт через `@langfuse/otel`; менять весь AI-клиент на автоматическую OpenAI-обёртку не требуется.
- Проверенные npm-версии: `@langfuse/tracing` 6.1.1, `@langfuse/otel` 6.1.1 (Node >=22), `@opentelemetry/sdk-node` 0.300.0 (Node >=22.15.0). При установке обнаружен peer-конфликт этой версии с Langfuse. Рабочая комбинация: `@opentelemetry/sdk-trace-node` 2.12.0 и `@opentelemetry/api` 1.9.1, как в документации изолированного TracerProvider Langfuse. Версии закреплены, npm install прошёл без force/legacy-peer-deps. Обе SDK Langfuse — 6.1.1. Пакет sdk-trace-node помечен upstream как deprecated в пользу нового sdk-trace; обновление нужно проверять вместе с требованиями Langfuse, а не обходить несовместимые peers.
- Последний опубликованный серверный релиз в момент проверки: Langfuse v4.75.0. SDK JS v6 требует сервер v4.59.0 или новее. При развёртывании закрепить конкретные версии образов, не использовать плавающий `latest`.
- Ядро Langfuse имеет MIT-лицензию; каталоги Enterprise и сторонние компоненты имеют отдельные условия.

## Данные для первого подключения

Разрешённый набор: случайный технический идентификатор вызова, среда, тип операции, провайдер, фактическая модель, длительность, номер попытки, HTTP-класс/безопасный код ошибки, usage из ответа провайдера. Для стоимости сохранять источник и версию тарифа; неизвестный usage или стоимость не заменять нулём.

Не передавать: prompt, ответ модели, тексты пациентов, ФИО, контакты, коды продолжения, access tokens, cookies, медицинские записи, изображения и аудиофайлы. Не передавать произвольные error.message: они могут содержать фрагменты тела ответа или запроса. Первая версия использует только разрешённые поля; ошибка экспорта не должна включать тело ответа Langfuse в логи.

Cached/reasoning/audio usage сохранять как детали и учитывать по правилам провайдера, без двойного сложения с уже включающими их totals. Передавать только фактически полученные показатели, не пытаться восстановить токены по тексту пациента. Не добавлять реальный patient/session ID в trace на первом этапе.

Наблюдаемость выключена по умолчанию. Первое включение — только для проекта с DEPLOYMENT_PURPOSE=test. Адрес и ключи Langfuse хранятся отдельно от OpenAI/Supabase; ключи не попадают во frontend. Для serverless обязательно завершение observations и forceFlush до завершения функции либо через поддерживаемый механизм продолжения выполнения. Не использовать несуществующий здесь Next.js `after` без адаптации к обычным Vercel Functions.

## Развёртывание сервера

Langfuse — отдельный сервис: Web, Worker, PostgreSQL, ClickHouse, Redis/Valkey и S3-совместимое хранилище. Это не ещё одна база пациентов Supabase и не модуль, который целиком запускается внутри текущего Vercel-проекта.

Для пилота доступен официальный Docker Compose. Официальный ориентир для VM: минимум 4 ядра, 16 GiB RAM, пример диска 100 GiB; это рекомендация документации, а не уже заказанный сервер. Compose сам по себе не обеспечивает HA и резервное копирование.

В текущей рабочей среде Docker отсутствует; адрес управляемого нами экземпляра и его ключи не предоставлены. Ничего не арендовано и аккаунты не созданы. Этап 2 можно выполнять без сервера с поддельным exporter; реальная доставка на этапе 3 требует доступного экземпляра. Владелец выбрал временное размещение в Langfuse Cloud с последующим переносом на наш сервер. Сайт Cloud открыт на форме входа; учётная запись и проект ещё не настроены. Отправка реальных событий не включена.

## Изменения в этой итерации

Подготовлены и локально проверены официальный SDK-адаптер, нормализация usage и передача счётчиков через маршрутизатор. Включение возможно только при AI_TELEMETRY_ENABLED=true, DEPLOYMENT_PURPOSE=test и наличии адреса/ключей. Изолированный TracerProvider не регистрирует автоматический сбор HTTP, БД и содержимого запросов; каждое текстовое обращение создаёт отдельное generation-событие. Экспорт имеет ограниченный timeout и flush перед завершением вызова; ошибки экспорта не повторяют AI-вызов.

Локальные проверки используют синтетические данные и in-memory exporter настоящего SDK. Langfuse считает оценочную стоимость по usageDetails и model после настройки облачного проекта; стоимость ещё не проверена на его UI и не синхронизируется обратно в estimated_cost внутреннего журнала. STT и отдельный голосовой анализ пока не инструментированы; фото в текстовых vision-вызовах не экспортируется, но токены учитываются.

Внешние AI-вызовы, отправка в Langfuse Cloud, миграции, commit, push и публикации не выполнялись. Для этапа 3 требуется вход/регистрация в Cloud и проект с серверными ключами.

## Публикация тестовой ветки

Владелец установил переменные Cloud в Preview и Production проекта tochka-opori-test и разрешил commit/push тестовой ветки. Перед выпуском добавлен build smoke: только Preview ветки feat/langfuse-test-observability отправляет одну generation synthetic-no-charge с нулевыми токенами, затем запрашивает через Observations API v2 ровно её traceId в ограниченном временном окне и проверяет отсутствие input/output. OpenAI и БД пациентов не вызываются. Неверная конфигурация или неподтверждённая доставка останавливают эту Preview-сборку. В main и остальных ветках smoke пропускается. Production в этой задаче не публикуется.
