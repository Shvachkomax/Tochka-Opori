
## Доступ к серверному черновику из кабинета врача — этап 7

- Из существующего **авторизованного** \`SpecialistCabinet\` (а не из публичного \`/specialist/my-practice/demo\`) добавлен раздел **«Моя практика · серверные черновики»**. Дополнительный фронтенд-флаг \`VITE_ENABLE_MY_PRACTICE_SERVER_UI=true\` только в Preview выбранной ветки.
- Врач самостоятельно нажимает **«Загрузить серверный черновик»**. Браузер отправляет \`POST /api/specialist\`, \`credentials: same-origin\`; сохранённая HttpOnly-сессия уже создана исходным кабинетом. Не передавать токен в URL или localStorage.
- Организации приходят только из серверной проверенной роли врача. Фиктивные «Север/Центр/Юг» публичной демоверсии **не** сопоставляются автоматически с реальными организациями. Для каждой разрешённой организации отдельные учебные услуги, цена/длительность/формат, учебные блоки и записи.
- **Учебные названия услуг выбираются из фиксированного списка**, текстовых полей для пациентов и медицинских заметок нет; псевдонимы пациентов строго \`demo-p1..demo-p4\`. Остальные поля проходят повторную серверную проверку.
- Локальные изменения на экране не попадают в БД до явного **«Сохранить на тестовом сервере»**. При HTTP 409 не перезаписывать автоматически. Повторная загрузка с сервера требует подтверждения потери несохранённых правок.
- Из другого устройства с тем же авторизованным врачом можно получить последнюю сохранённую версию. Никакой синхронизации с МИС или настоящими пациентами.
- Имеющаяся тестовая таблица \`my_practice_synthetic_workspaces\` уже создана в \`Tochka-Opori-Preview-Test\`, RLS включена, прямые \`anon/authenticated\` доступы отсутствуют. Продолжать строго без реальных ПДн.
- Перед активацией серверного API администратор должен в Vercel → \`tochka-opori-test\` → Environment Variables создать **для этой git-ветки Preview** переменные \`SUPABASE_URL\` (URL существующей тестовой Supabase), \`SUPABASE_SERVICE_ROLE_KEY\` (ключ **именно этой тестовой** базы — вводить только в Vercel, не в чат), \`MY_PRACTICE_ALLOWED_SUPABASE_REF=eehyehlhiyztciaezaus\`, \`MY_PRACTICE_SERVER_ENABLED=true\`.
- **Запрещено** включать \`MY_PRACTICE_SERVER_ENABLED=true\` без проверки, что пара \`SUPABASE_URL\` / \`SUPABASE_SERVICE_ROLE_KEY\` указывает на один и тот же *тестовый* проект. Никаких правок общих preview или production переменных.
- После сохранения переменных нужен новый Preview-деплой ветки, проверка \`getMyPracticeWorkspace\` и \`saveMyPracticeWorkspace\`, межклинической изоляции и конфликтов 409. Только затем считать серверную синхронизацию действующей.
